# 과제: 온톨로지 정합성 검증 및 디버깅

## 과제 개요

이번 과제에서는 고의로 논리적 모순을 만들어 온톨로지의 일관성 제약 조건과 충돌시키는 시나리오를 구성해 봅니다.

## 요구사항

1. **상호 배타적 클래스(Disjoint Classes) 설계:**
   - 여러분이 운영하는 커머스 플랫폼에서 서로 절대 겹칠 수 없는 두 가지 유저 그룹(클래스)을 정의해 보세요.
   - 예: `개인회원(B2C_User)`과 `기업회원(B2B_User)`은 서로소(Disjoint) 관계이다.

2. **단일값 속성(Functional Property) 설계:**
   - 한 인스턴스가 오직 하나의 값만 가져야 하는 속성을 정의해 보세요.
   - 예: 하나의 주문(Order)은 오직 하나의 `주문일시(orderDate)`만 가질 수 있다.

3. **모순 상황(Inconsistency Scenario) 시뮬레이션:**
   - 위에서 정의한 제약 조건을 어기는 잘못된 데이터(인스턴스)가 들어오는 상황을 구상하여 트리플 형태로 작성하세요.
   - 예:
     ```text
     # 1번 제약 위반 상황
     User_John rdf:type B2C_User .
     User_John rdf:type B2B_User .
     ```

4. **디버깅 방안 서술:**
   - 추론 엔진이 이 모순을 발견하여 경고를 띄웠을 때, 데이터 엔지니어로서 이 문제를 어떻게 해결(디버깅)할 것인지 서술하세요. (예: 잘못된 데이터 소스 확인, 속성 수정 등)

## 제출 형식

- 작성한 설계와 시나리오, 디버깅 방안을 Markdown 문서 형식으로 정리하여 제출하세요.
