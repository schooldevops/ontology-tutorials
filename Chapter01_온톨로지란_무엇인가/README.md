# 1강: 온톨로지란 무엇인가?

## 강의 개요

이번 강의의 목표는 온톨로지를 "어려운 철학 용어"가 아니라, 기업 데이터와 AI가 같은 의미 체계를 공유하게 만드는 지식 모델링 방식으로 이해하는 것입니다.

일반적인 데이터베이스는 데이터를 저장하고 조회하는 데 강합니다. 반면 온톨로지는 데이터가 무엇을 의미하는지, 개념들이 서로 어떤 관계를 가지는지, 명시되지 않은 지식을 어떻게 추론할 수 있는지를 다룹니다.

## 학습 목표

- 데이터, 정보, 지식의 차이를 설명할 수 있다.
- RDBMS 데이터 모델과 온톨로지 지식 모델의 차이를 구분할 수 있다.
- DIKW 피라미드 관점에서 기업 데이터가 지식으로 전환되는 과정을 이해한다.
- 시맨틱 웹과 지식 표현의 기본 아이디어를 설명할 수 있다.

## 핵심 질문

1. 데이터베이스에 값이 저장되어 있다는 것과, 시스템이 그 값의 의미를 안다는 것은 어떻게 다른가?
2. `customer_id`, `user_id`, `member_id`가 모두 같은 사람을 가리킬 때, 시스템은 그것을 어떻게 알 수 있는가?
3. AI 에이전트가 기업 업무를 수행하려면 단순 테이블보다 어떤 추가 지식이 필요한가?

## 1. Data, Information, Knowledge

### Data

데이터는 관찰되거나 저장된 원시 값입니다.

예:

| user_id | order_id | amount | created_at |
| --- | --- | ---: | --- |
| U001 | O1001 | 59000 | 2026-05-01 |

이 값만 보면 "U001이 O1001 주문으로 59,000원을 결제했다"는 사실을 사람이 해석할 수는 있지만, 시스템이 그 의미를 자동으로 이해한다고 보기는 어렵습니다.

### Information

정보는 데이터에 맥락이 붙은 상태입니다.

예:

- `amount`는 결제 금액이다.
- `created_at`은 주문 생성 시각이다.
- `user_id`는 주문한 고객을 식별한다.

정보 단계에서는 컬럼의 의미와 업무 맥락이 드러납니다.

### Knowledge

지식은 개념, 관계, 규칙이 함께 표현된 상태입니다.

예:

- 고객은 주문을 생성한다.
- 주문은 상품을 포함한다.
- 일정 기간 동안 반복 구매한 고객은 충성 고객으로 분류될 수 있다.
- 구독 상품을 구매한 고객은 구독 상태를 가진다.

온톨로지는 이 지식 단계를 기계가 처리 가능한 형태로 표현하는 모델입니다.

## 2. DIKW 피라미드

DIKW는 Data, Information, Knowledge, Wisdom의 약자입니다.

```text
Wisdom     어떤 의사결정을 해야 하는가?
Knowledge  어떤 규칙과 관계가 존재하는가?
Information 데이터가 어떤 맥락을 가지는가?
Data       어떤 값이 저장되어 있는가?
```

엔터프라이즈 AI에서 중요한 것은 데이터가 많은지가 아니라, 데이터가 의사결정 가능한 지식 구조로 정리되어 있는지입니다.

예를 들어 다음 질문을 생각해봅니다.

> 최근 3개월간 이벤트 A로 유입되어 구독을 유지 중이고, CS 불만이 증가한 고객군은 누구인가?

이 질문에 답하려면 단순히 주문 테이블만 보면 부족합니다. 고객, 이벤트, 구독, 결제, CS 티켓이 하나의 의미 네트워크로 연결되어 있어야 합니다.

## 3. RDBMS 모델과 온톨로지 모델의 차이

### RDBMS 중심 사고

RDBMS는 데이터를 정규화된 테이블에 저장하고, 키와 조인을 통해 조회합니다.

```sql
SELECT u.name, o.order_id, p.name
FROM users u
JOIN orders o ON u.user_id = o.user_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p ON oi.product_id = p.product_id;
```

이 모델은 명확한 스키마와 트랜잭션 처리에 강합니다. 하지만 다음 질문에는 약해질 수 있습니다.

- `users`와 `members`는 같은 개념인가?
- `Product`와 `SubscriptionPlan`은 어떤 상위 개념을 공유하는가?
- 고객이 이벤트를 통해 유입되었고 이후 구독을 시작했다는 업무 의미는 어디에 표현되는가?
- 명시되지 않은 관계를 추론할 수 있는가?

### 온톨로지 중심 사고

온톨로지는 개념과 관계를 중심으로 지식을 표현합니다.

```text
Customer --places--> Order
Order --contains--> Product
Customer --participatesIn--> Event
Customer --subscribesTo--> SubscriptionPlan
SubscriptionPlan --isA--> Product
```

여기서 중요한 것은 테이블 구조가 아니라 "업무 세계에 어떤 객체가 있고, 그 객체들이 어떤 의미 관계를 가지는가"입니다.

## 4. 시맨틱 웹과 지식 표현

시맨틱 웹은 웹의 리소스와 데이터에 의미를 부여해 기계가 해석할 수 있도록 만들자는 아이디어입니다.

온톨로지에서는 보통 지식을 다음과 같은 트리플 구조로 표현합니다.

```text
Subject   Predicate        Object
고객U001   purchased        상품P001
상품P001   type             SubscriptionProduct
고객U001   participatedIn   이벤트E001
```

트리플은 단순하지만 강력합니다. 여러 트리플이 연결되면 지식 그래프가 됩니다.

## 5. 엔터프라이즈 관점에서 온톨로지가 필요한 이유

기업 시스템은 보통 부서와 목적에 따라 나뉩니다.

- CRM: 고객 관리
- ERP: 주문, 재고, 회계
- CS: 문의와 불만 처리
- Marketing: 캠페인과 이벤트
- Subscription: 구독 상태와 결제 주기

각 시스템은 자기 언어로 데이터를 정의합니다. 같은 사람을 어떤 시스템은 `customer`, 어떤 시스템은 `member`, 어떤 시스템은 `subscriber`라고 부를 수 있습니다.

온톨로지는 이런 용어와 개념을 하나의 의미 체계로 연결합니다.

```text
CRM.Customer
ERP.Buyer
CS.Requester
Subscription.Subscriber
        |
        v
CoreOntology.User
```

이 구조가 있어야 AI 에이전트가 "고객"이라는 말을 들었을 때 어떤 시스템의 어떤 데이터를 함께 봐야 하는지 판단할 수 있습니다.

## 6. 이번 강의의 핵심 정리

- 데이터 모델은 저장 구조를 설명한다.
- 지식 모델은 개념, 관계, 규칙을 설명한다.
- RDBMS는 업무 데이터를 안정적으로 저장하고 처리하는 데 강하다.
- 온톨로지는 여러 데이터의 의미를 통합하고 추론 가능한 구조로 만드는 데 강하다.
- 엔터프라이즈 AI는 데이터베이스만으로 충분하지 않고, 업무 의미를 담은 온톨로지 계층이 필요하다.
