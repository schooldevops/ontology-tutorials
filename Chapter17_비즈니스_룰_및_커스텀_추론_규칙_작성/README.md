# 17강: 비즈니스 룰 및 커스텀 추론 규칙 작성

## 강의 개요

16강에서는 파편화된 데이터(이벤트, 결제, CS)를 온톨로지로 통합하여 관계를 설정했습니다. 17강에서는 이렇게 통합된 지식 그래프 위에서 동작하는 **동적 비즈니스 룰(Business Rule)** 을 작성하고 적용하는 방법을 배웁니다.

기업은 단순히 데이터를 저장하는 것에 그치지 않고, "조건 A와 B가 충족되면 새로운 상태 C를 부여한다"와 같은 논리적 규칙을 통해 자동화된 의사결정을 내리길 원합니다. 온톨로지에서는 명시적으로 데이터를 입력하지 않더라도, SWRL(Semantic Web Rule Language) 같은 규칙 언어를 활용해 추론기(Reasoner)가 새로운 지식을 스스로 도출하게 만들 수 있습니다.

## 학습 목표

- 온톨로지의 추론 기능이 비즈니스 룰 엔진으로 어떻게 활용되는지 이해한다.
- SWRL(Semantic Web Rule Language)의 기본 문법을 파악하고 간단한 룰을 작성할 수 있다.
- 정해진 조건(예: 체류 기간, 구매 금액)에 따라 새로운 지식(예: VIP 등급 부여)을 동적으로 생성하는 과정을 모델링할 수 있다.
- 절차적 코드(If-Else)와 선언적 추론(Ontology Reasoning)의 차이점을 설명할 수 있다.

## 핵심 질문

1. "VIP 고객"이라는 속성을 데이터베이스에 직접 업데이트하는 방식과, 온톨로지 추론을 통해 동적으로 판단하는 방식의 차이는 무엇인가?
2. SWRL 룰에서 여러 조건을 어떻게 결합(AND 조건)하여 표현할 수 있는가?
3. 규칙을 통해 새롭게 생성된 데이터(Inferred Data)를 어떻게 비즈니스 워크플로우에 활용할 수 있는가?

## 1. 절차적 코드 vs 선언적 추론

일반적인 개발 환경에서는 배치 프로그램이나 서비스 로직 내부에 조건문(If-Else)을 작성하여 등급을 업데이트합니다.

**절차적 접근 (예: Java/Python)**
```python
if user.subscription_months >= 6 and user.total_purchase >= 500:
    user.set_grade("VIP")
    db.save(user)
```
- 단점: 로직이 코드 깊숙이 숨겨져 있어 비즈니스 담당자가 룰을 파악하고 변경하기 어렵습니다.

**선언적 접근 (Ontology + SWRL)**
- 온톨로지 모델에 비즈니스 룰을 지식의 형태로 명시합니다. 추론기가 데이터를 읽을 때 해당 룰에 부합하는 인스턴스에 자동으로 'VIP' 속성을 부여합니다.
- 장점: 룰 자체가 모델의 일부가 되므로 관리가 투명하고, 데이터 변경 시 실시간 추론이 가능합니다.

## 2. SWRL (Semantic Web Rule Language) 기초

SWRL은 OWL 온톨로지를 위한 규칙 언어로, `Antecedent(조건부) -> Consequent(결론부)` 형태로 구성됩니다.

**기본 문법 구조:**
```text
ClassA(?x) ^ PropertyP(?x, ?y) -> ClassB(?x)
```
- `?x`, `?y`: 변수(Variable)
- `^`: 논리곱(AND)
- `->`: 함의(Implies / Then)

**해석:** "?x가 ClassA에 속하고, ?x가 ?y와 PropertyP 관계를 맺고 있다면, ?x는 ClassB에 속한다."

## 3. 실무 예제: 조건부 승급 룰 작성

**비즈니스 요구사항:**
"어떤 사용자(User)가 '활성 상태(Active)'의 구독(Subscription)을 가지고 있고, 그 구독의 누적 개월 수(monthsActive)가 6개월 이상이며, 해당 사용자의 총 구매액(totalSpent)이 500 이상일 경우, 그 사용자를 VIP 등급(VIPUser)으로 분류한다."

**SWRL 규칙 표현:**
```text
User(?u) ^ 
hasSubscription(?u, ?s) ^ 
Subscription(?s) ^ 
hasStatus(?s, "Active") ^
monthsActive(?s, ?m) ^ swrlb:greaterThanOrEqual(?m, 6) ^
totalSpent(?u, ?t) ^ swrlb:greaterThanOrEqual(?t, 500)
-> VIPUser(?u)
```

- `swrlb:`는 SWRL Built-in 함수로, 숫자 비교, 문자열 조작 등의 연산을 지원합니다.
- 위 룰이 온톨로지 엔진(Pellet, HermiT 등)에 등록되면, 조건을 만족하는 인스턴스는 자동으로 `VIPUser` 클래스에 속하게 됩니다.

## 4. 커스텀 룰을 활용한 지식 그래프의 확장

비즈니스 룰을 통해 온톨로지는 정적 저장소를 넘어 살아있는 '규칙 엔진'이 됩니다.
- **리스크 관리:** "이탈 확률 점수가 특정 수치를 넘고, 최근 1주 내 환불 티켓이 있으면 '이탈 위험군(ChurnRiskUser)'으로 분류"
- **추천 시스템:** "A 카테고리 상품을 3회 이상 구매한 고객은 'A 매니아'로 분류 -> 특정 프로모션 타겟에 자동 포함"
- **할인 적용:** "이벤트 참여 내역이 있고, 특정 상품군을 보고 있다면 임시 할인 쿠폰 발행 대상자로 추론"

## 5. 이번 강의의 핵심 정리

- SWRL과 같은 규칙 언어를 이용하면 온톨로지 위에 비즈니스 도메인의 룰을 명시적으로 선언할 수 있다.
- 선언적 룰 작성은 로직을 투명하게 관리하게 해 주며, 추론기를 통해 동적으로 새로운 지식(인스턴스의 클래스 분류, 속성 추가)을 자동 생성한다.
- 이렇게 생성된 추론 결과는 플랫폼의 다른 시스템(마케팅 자동화, 알림 시스템 등)이 즉각적인 Action을 취하는 트리거가 될 수 있다.
