# 과제: 비즈니스 룰 및 커스텀 추론 규칙 작성

## 과제 개요

이번 과제에서는 17강에서 학습한 내용과 SWRL 개념을 바탕으로, 비즈니스 요구사항을 논리적인 추론 규칙으로 변환하는 연습을 합니다.

## 요구사항

1. **상황 분석 및 조건 도출:**
   당신은 커머스 플랫폼의 데이터 설계자입니다. 운영팀에서 다음과 같은 비즈니스 룰을 온톨로지 시스템에 추가해 달라고 요청했습니다.
   
   **요청사항:** "최근 3개월 내에 환불(Refund) 관련 CS 티켓을 2번 이상 생성(raisedBy)한 고객(User)이면서, 현재 이용 중인 구독(Subscription)의 상태(status)가 'Active'인 경우, 해당 고객을 '요주의 고객(AtRiskUser)' 클래스로 분류해 주세요."

2. **규칙 변환 설계:**
   위의 자연어 요구사항을 바탕으로 어떤 클래스와 프로퍼티, 그리고 Built-in 함수가 필요한지 나열하세요.
   - 예) `User`, `CSTicket`, `raisedBy`, `ticketCount` 등 필요한 요소를 자유롭게 가정하여 설계하세요.

3. **SWRL(또는 가상의 논리 규칙) 작성:**
   도출한 조건들을 조합하여 SWRL 문법과 유사한 형태로 룰을 작성하세요.
   - 형태 예시: `Condition A ^ Condition B ^ Condition C -> Result`
   
4. **추가 아이디어 제안 (선택 사항):**
   '요주의 고객(AtRiskUser)'으로 추론된 고객 데이터를 활용하여, Palantir 등 플랫폼의 Action 계층에서 어떤 후속 조치(예: 자동 할인 쿠폰 발송, 전담 상담사 배정 등)를 취할 수 있을지 아이디어를 서술하세요.

## 제출 형식

- 작성한 비즈니스 룰 설계와 논리 식을 Markdown 포맷으로 작성하여 제출하세요.
